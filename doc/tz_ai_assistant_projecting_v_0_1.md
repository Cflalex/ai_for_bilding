# Техническое задание 0.1
## AI-ассистент проектировщика

---

# 1. Цель проекта

Разработать AI-ассистента проектировщика, который на этапе формулирования задания на проектирование помогает заказчику и проектировщику автоматически определить состав проектной документации, перечень необходимых разделов, подразделов, исходных данных, нормативных требований и типовых проектных решений.

Основой формализации задания является Постановление Правительства РФ №87 «О составе разделов проектной документации и требованиях к их содержанию», поскольку оно определяет обязательный состав разделов проектной документации для объектов капитального строительства.

---

# 2. Идея системы

AI-ассистент должен принимать первичное описание объекта в свободной форме.

Пример:

> «Нужно спроектировать автоматизированную газовую котельную для производственного здания»

После этого система должна:

1. определить тип объекта;
2. выделить ключевые проектные признаки;
3. сопоставить их с требованиями ПП №87;
4. определить обязательные разделы проектной документации;
5. определить, какие подразделы инженерных систем требуются;
6. сформировать список данных, которые нужно запросить у заказчика;
7. подтянуть релевантные СП, ГОСТ, СНиП, технические условия, архивные решения и примеры пояснительных записок;
8. подготовить структурированную основу ТЗ.

---

# 3. Роль Постановления №87

ПП №87 используется как нормативный каркас системы.

Сущности системы должны извлекаться в первую очередь из структуры и содержания ПП №87, а не задаваться произвольно разработчиком. Постановление рассматривается как исходная нормативная онтология проектной документации.

Из ПП №87 должны быть выделены следующие типы сущностей:

- объект капитального строительства;
- вид объекта;
- раздел проектной документации;
- подраздел проектной документации;
- текстовая часть;
- графическая часть;
- требование к содержанию раздела;
- исходные данные;
- инженерная система;
- проектное решение;
- расчет;
- схема, план, чертеж;
- условие применимости требования.

Система должна извлекать из ПП №87:

- виды объектов капитального строительства;
- обязательные разделы проектной документации;
- требования к текстовой части;
- требования к графической части;
- условия применимости отдельных разделов;
- связи между типом объекта, инженерными системами и составом проектной документации.

Постановление рассматривается как формализованная структура требований к проекту.

Архив ранее выполненных проектов рассматривается как отдельный перспективный источник данных. В дальнейшем система сможет сравнивать нормативную структуру проекта по ПП №87 с фактической структурой похожих проектов из архива, чтобы выявлять типовые решения, отклонения и недостающие элементы. На этапе версии 0.1 подключение и разметка архива фиксируются как направление дальнейшего развития, но не входят в обязательный объем MVP.

---

# 4. Основные функции AI-ассистента

## 4.1. Нормализация первичного задания

Система должна преобразовывать свободное описание заказчика в структурированную форму:

- тип объекта;
- назначение объекта;
- производственный / непроизводственный / линейный объект;
- новое строительство / реконструкция / капитальный ремонт;
- наличие инженерных систем;
- наличие технологического процесса;
- наличие опасных факторов;
- потребность в ресурсах: электричество, вода, тепло, газ;
- необходимость пожарной безопасности;
- необходимость мероприятий для МГН;
- необходимость сметы;
- необходимость этапности строительства.

---

## 4.2. Формирование состава проектной документации

На основании нормализованного задания система должна определить состав разделов проектной документации по ПП №87.

Результат должен быть представлен в виде структуры:

| Раздел | Нужен | Основание | Что требуется |
|---|---|---|---|
| Пояснительная записка | Да | ПП №87 | Исходные данные, ТЭП, описание объекта |
| Архитектурные решения | Да | ПП №87 | Планы, фасады, описания |
| Конструктивные решения | Да | ПП №87 | Схемы, нагрузки, материалы |
| Инженерные системы | Да | ПП №87 | Электроснабжение, отопление, водоснабжение |
| Пожарная безопасность | Да | ПП №87 | Мероприятия и расчёты |

---

## 4.3. Формирование перечня исходных данных

Система должна автоматически формировать перечень данных, которые необходимо запросить у заказчика.

Примеры:

- градостроительный план земельного участка;
- технические условия на подключение;
- сведения о мощности объекта;
- сведения о потреблении ресурсов;
- сведения о технологическом оборудовании;
- результаты инженерных изысканий;
- архивные чертежи и документация.

---

## 4.4. Подбор нормативной базы

После определения типа объекта и состава проектной документации система должна подбирать релевантные нормативные документы:

- СП;
- ГОСТ;
- СНиП;
- технические регламенты;
- отраслевые нормативы;
- внутренние стандарты организации.

На первом этапе допускается использование демонстрационной базы нормативных правил в YAML/JSON-формате.

---

## 4.5. Использование архива проектных решений

Система должна подключаться к архиву проектной организации и находить похожие решения:

- типовые узлы;
- фрагменты чертежей;
- пояснительные записки;
- схемы инженерных систем;
- спецификации;
- ранее разработанные проекты.

Проектирование рассматривается как сборка проекта из проверенных инженерных решений.

---

## 4.6. Подготовка пояснительной записки

Система должна автоматически формировать черновик пояснительной записки на основании:

- структуры ПП №87;
- типа объекта;
- найденных разделов проектной документации;
- доступных исходных данных;
- архивных пояснительных записок;
- выбранных инженерных решений.

На этапе формирования ТЗ система должна:

1. создавать шаблон пояснительной записки;
2. автоматически заполнять известные данные;
3. отмечать отсутствующие данные;
4. связывать разделы пояснительной записки с соответствующими разделами проекта;
5. использовать архив организации как источник типовых формулировок и структуры.

Пояснительная записка рассматривается как динамический документ, который постепенно уточняется по мере развития проекта.

---

# 5. Архитектура решения

Минимальная архитектура системы:

1. Модуль ввода ТЗ;
2. Модуль нормализации задания;
3. Граф ПП №87;
4. Граф нормативных требований;
5. RAG-модуль;
6. Модуль генерации ТЗ;
7. Модуль проверки полноты;
8. Модуль генерации пояснительной записки.

---

# 6. Первый MVP

Сценарий MVP:

«Формирование структуры ТЗ для автоматизированной газовой котельной».

MVP должен:

1. принять текстовое описание объекта;
2. определить тип объекта;
3. найти в графе ПП №87 нужные разделы;
4. определить обязательные инженерные подразделы;
5. подтянуть базовые нормативные ограничения;
6. сформировать черновик ТЗ;
7. сформировать шаблон пояснительной записки;
8. вывести список недостающих исходных данных.

---

# 7. Результат работы системы

На выходе AI-ассистент должен формировать:

- структурированное ТЗ;
- перечень разделов проектной документации;
- перечень исходных данных;
- перечень применимых нормативных документов;
- список проектных решений из архива;
- список вопросов к заказчику;
- карту неполноты задания;
- черновик пояснительной записки.

---

# 8. Главный принцип

AI-ассистент не заменяет проектировщика полностью.

Система выступает как нормативный и инженерный помощник:

- помогает не забыть обязательные разделы;
- структурирует проектное задание;
- подтягивает релевантные нормативы;
- ищет похожие инженерные решения;
- ускоряет подготовку проектной документации;
- автоматически формирует основу пояснительной записки.

Главная задача системы — сократить объём ручной рутинной работы и повысить повторное использование накопленного инженерного опыта организации.
